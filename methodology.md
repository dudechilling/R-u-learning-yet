# Publishing and accuracy rules

This project is a question-first reference, not an assessment answer bank.

Every problem must explain: what the question asks; which inputs are known, missing, or unknown; why the method fits; the exact steps in RStudio; runnable R code; the interpretation; and at least one condition that could make the answer misleading.

Use independently authored examples and small, clearly labeled invented datasets. Do not copy private teaching resources, protected worksheets, personal records, or unpublished solutions. Attribute any compatible external code or dataset. No redistribution license has yet been selected for original material.

Run every script in a clean R session. Review mathematical accuracy and distinguish sample results from population claims. Graphs must identify variables, units, counted categories, and fitted curves. Use readable text and at least one non-color distinction when lines represent different statistics. Include warnings about selection bias, missing values, model assumptions, and causation when relevant.

The console index uses deterministic keyword search, not an artificial-intelligence model. A selected decision route is only as reliable as the provided inputs; the route must never infer that an unmentioned input is absent. Do not publish generated logs, temp data, cached site outputs, or duplicate candidate files.
